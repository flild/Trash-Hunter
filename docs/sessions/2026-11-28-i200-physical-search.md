# I-200 · Физический поиск

28 ноября 2026 года. Unity 6000.6.9f1, сцена ContainerSearch, ветка `main`. Исходная ревизия `74c4b4e`. Следующий этап — I-130.

## Что изменилось

Вскрытие мешка или коробки записывает в автослот открытое состояние оболочки и начальные позы всех экземпляров, которые ещё числятся внутри. После записи эти же объекты получают физическое движение. Если место выхода занято, игрок может убрать помеху и повторить действие. Формат автослота сохранён. Владелец подтвердил изменение записи и замену списка физическим вскрытием в ходе I-200.

В мире зажатая ЛКМ тянет вещь, отпускание роняет её с текущей позиции, ПКМ бросает. В осмотре и сумке мышь принадлежит открытому экрану. Shift включает бег, прыжок проверяет опору и быстрее возвращает игрока на землю. У цели компактная подпись, памятка в нижнем левом углу переключается клавишей H.

К существующему наполнению добавлены 115 обрезков картона, дерева и металла. Один статический меш с тремя материалами использует исходную геометрию и материалы проекта. У обрезков нет коллайдеров и физических тел. [Скрипт подготовки сцены](../../AgentScripts/Authoring/AuthorPileScraps.cs).

## Проверка в Editor

[Игровой маршрут](../../AgentScripts/Verification/VerifyPhysicalSearch.cs) прошёл отдельно на RU и EN с клавиатурой и мышью Input System. Для каждого прогона использована отдельная копия [фикстуры I-110](../../AgentScripts/Fixtures/i110-pile-measurement.json) в `Logs/I-200/`, seed 706296053.

- Сдвинут деревянный ящик. Обе упаковки вскрыты с прохода. Из каждой выпали два движущихся тела. Повторное вскрытие сохранило ревизию слота. Блокировка `slot.pending` перед первым открытием оставила файл и содержимое мешка в исходном состоянии, повтор после снятия блокировки прошёл.
- Выпавший моторчик поднят, осмотрен, остался в руке при отпускании кнопки в осмотре и сумке, затем брошен по ПКМ. Отдельно проверено падение ящика при отпускании ЛКМ. Имя у прицела и переключение памятки проверены в обеих локалях. На кадре 1280×720 видны моторчик с подписью, прицел, памятка и доступный выход. Кадр хранится локально в `Logs/I-200/search-hud.png`.
- Из контейнера выполнен выход через борт по E. На площадке скорость ходьбы 3,20 м/с, бега 5,28 м/с. От ввода прыжка до посадки прошло 0,63 с на RU и 0,61 с на EN.
- После сохранения и отдельного запуска Play Mode совпали позиции и повороты двух упаковок и четырёх выпавших вещей. На старой версии штатным выбором из списка создан частичный слот. После его загрузки в новой версии вилка осталась доступна, вскрытие освободило только оставшийся моторчик.
- Компиляция прошла. Во время подключения Pipeline зарегистрировал ошибку неизвестной команды `asset refresh`; штатная перекомпиляция прошла через `script recompile`. После игровых прогонов новых ошибок не появилось. Восстановлены Edit Mode и переменные каталога сохранений и языка.

Проверены 270 локальных ссылок и наличие пар для 146 ключей RU/EN. В staged diff Git отметил концевые пробелы только в пустых полях нового меша и его метаданных, записанных Unity.

## Кадр на одной укладке

[Замер](../../AgentScripts/Verification/MeasurePackageOpening.cs) на двух копиях одного слота, одна камера, Game View 932×524, VSync отключён. В каждой фазе записано 122–125 кадров камеры. До изменения нажатие открывало список, после него появились два физических тела.

| Состояние | Медиана, мс | p95, мс | Максимум, мс | Медиана вызовов отрисовки |
|---|---:|---:|---:|---:|
| До, покой | 9,01 | 10,49 | 33,14 | 338 |
| После, покой | 8,09 | 9,04 | 9,91 | 344 |
| До, вскрытие | 9,15 | 12,72 | 57,85 | 342 |
| После, вскрытие | 8,11 | 9,47 | 64,74 | 364 |

При вскрытии выросли максимум времени кадра и число вызовов отрисовки. Это короткий замер одной укладки в Editor. Другие seed, предельная нагрузка и отдельный Windows Player в I-200 не проверялись. Предыдущие сборки относятся к прежним этапам.

Для повторения установить в процессе Editor `TRASH_HUNTER_EDITOR_SAVE_DIR` на новый каталог с копией фикстуры под именем `slot.json`. Задать `TRASH_HUNTER_LOCALE` как `ru` или `en`, запустить Play Mode в ContainerSearch и выполнить одну команду на копию слота.

```powershell
$pipeline = @('--caller','plugin','--skill','unity-pipeline','--project-path','F:\UnityProjects\Trash-Hunter','--format','json')
unity command script eval @pipeline -- --file AgentScripts/Verification/VerifyPhysicalSearch.cs --timeout 50
# На отдельной исходной копии
unity command script eval @pipeline -- --file AgentScripts/Verification/MeasurePackageOpening.cs --timeout 45
```

Для проверки восстановления снова войти в Play Mode на сохранении полного маршрута и повторить первую команду. Для проверки старой упаковки использовать копию с открытым мешком, вилкой в руке и вложенным моторчиком. Для ручной проверки удержать ЛКМ на ящике и отвести его в сторону, отпустить, вскрыть упаковку щелчком, поднять одну из выпавших вещей. Q открывает осмотр, Tab — сумку, ПКМ при удержании бросает вещь.
