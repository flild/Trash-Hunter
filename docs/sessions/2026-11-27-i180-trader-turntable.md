# 27 ноября 2026 — I-180. Поручение старьёвщика

Поручение открывается после первой продажи. У старьёвщика J показывает
предложение, Enter принимает его. После принятия J снова показывает
модель РП-07 и место поиска у старьёвщика, дома и на вылазке. На вылазке
подсказка J доступна из паузы. У старьёвщика P для выбранного проигрывателя
открывает подтверждение. После Enter проигрыватель остаётся у игрока.
Старьёвщик сообщает о неисправности и открывает контакт мастера.

Использованы штатный журнал, инвентарь, окно вылазки и таблицы RU/EN.
Проигрыватель добавлен в [сцену поиска](../../Assets/TrashHunter/Scenes/ContainerSearch.unity)
через [скрипт авторинга](../../AgentScripts/Authoring/AuthorTraderTurntable.cs).
Он занимает 2 × 2 ячейки. Модель собрана из примитивов Unity с материалами
проекта и использует существующий шаблон таблички. Для первых двух попыток
выбран временный шанс 1 из 3. С третьей вылазки и далее модель появляется,
если поручение активно и проигрывателя нет в запасе.
[Контракт](../ARCHITECTURE.md#поручение-старьёвщика-i-180).

## Игровая проверка

Проверка переключает Play Mode между фазами из одного изолированного слота.
Запуск в Unity Editor 6000.6.9f1, CLI и Pipeline 1.0.0. Для ввода использованы
виртуальные клавиатура и мышь. Позиция игрока у выхода и рядом с находкой
устанавливается проверкой, сам подбор проходит штатным лучом и ЛКМ.

Для начальной фазы нужен автослот формата 2 у старьёвщика, вылазка 5,
касса 0, экипированная сумка, пустой мир и запас из `radio-a` с вылазки 1
и `dial-a` с вылазки 2 в указанном порядке. Проверенные `runId` для двух
пропусков и двух появлений соответственно:
`00000009000000000000000000000001` и `0000000d000000000000000000000001`.
Контрольная сумма envelope — SHA-256 полезной нагрузки в UTF-8, в Base64.
В процессе Editor задать `TRASH_HUNTER_EDITOR_SAVE_DIR` с абсолютным путём к
копии слота, `TRASH_HUNTER_LOCALE` и `TRASH_HUNTER_CHECK`. Фазы
`offer` / `offer-early`, `resume` и `finished` запускаются в отдельных
Play-сессиях, записанный слот передаётся следующей фазе без изменений.

~~~powershell
$pipeline = @('--caller','plugin','--skill','unity-pipeline','--project-path','F:/UnityProjects/Trash-Hunter','--format','json')
unity command script eval @pipeline -- --file AgentScripts/Verification/VerifyTraderTurntable.cs --timeout 85
unity command script eval @pipeline -- --file AgentScripts/Verification/VerifyQuestJournal.cs --timeout 30
~~~

Вторую команду выполнять в Edit Mode. Скрипты проверки лежат вне Assets.
Свежие прогоны дали 58 проверок в каждой локали (30 + 23 + 5), регрессия
журнала дала 18 проверок двух технических определений. Копия поискового
слота формата 2 с укладкой версии 2 прошла 7 проверок холодного старта
через `VerifySceneTransitions.cs` в фазе `cold`. Просмотрен кадр
окна результата EN при 1280 × 720. В отчётах Pipeline проверены открытие поручения после продажи, просмотр
условия, первые две попытки, гарантированная третья, повторная находка
после пропуска, F5 и холодное продолжение с прежними ID и позами. Проверка
также покрывает осмотр, укладку в сумку, сохранение экземпляра в запасе,
отказ для другой вещи, блокировку записи на принятии и предъявлении,
однократный контакт и повторный холодный старт у старьёвщика. Проверены
границы текста в обеих локалях. Unity Console после прогонов показала
0 ошибок. Относительные ссылки изменённых документов и ключи локализации
сверены. `git diff --check` отметил только пробелы после пустых полей,
записанные сериализатором Unity в сцене поиска.

Итоговый Windows Player, замеры и нагрузочная серия поездок относятся к I-190.
Обычный ручной проход можно проверить через первую продажу, J → Enter,
вылазку за РП-07 и P → Enter у старьёвщика. После сообщения о мастере РП-07
должен оставаться в запасе, а повторное нажатие P уже не открывает предъявление.
