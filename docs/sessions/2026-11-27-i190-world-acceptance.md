# I-190 — стабильность переходов и Windows Player

27 ноября 2026. Начало этапа на `d0037e3`, рабочее дерево было чистым.
Unity 6000.6.9f1, Unity CLI и Pipeline 1.0.0, Windows x64, Direct3D 12.

## Изменение

Генератор проверяет прежнюю сетку кандидатов от ближайшей точки к дальней.
При равном расстоянии действует прежний порядок по X и Z. Это сокращает
физические запросы по поверхности и окружению. Запись и резервирование
слота выполняются прежним путём, а обновление GameState и выгрузка дома
следуют за успешной записью. Маркеры `TrashHunter.PrepareDeparture` и
`TrashHunter.CommitDeparture` видны в Profiler. Для контрольного seed
`706302107` совпали все 27 записей укладки, включая позиции и повороты.

## Замеры

Сравнивались одинаковые копии
[слота I-110](../../AgentScripts/Fixtures/i110-pile-measurement.json) и

дом → старьёвщик → дом → поиск. Для холодного входа CPU включает Editor.

Для повторных вылазок Profiler показал максимум корутины перехода
77,9 → 53,5 мс (CPU-кадр 115,5 → 84,9 мс). После правки подготовка занимала
12,4–39,3 мс, запись 12,9–26,5 мс. До правки эти операции попадали в один
пик, остаток по измерениям координатора составлял 19,1–47,1 мс сверх
загрузки, записи, активации и представлений. Пробное разнесение работы
по кадрам увеличило задержку и было снято. На дисковый ввод-вывод и фоновые
расходы Editor приходится часть разброса. Численные бюджеты пока открыты.

Для обоих маршрутов после каждого из 25 переходов оставались один игрок,
одна камера, одна игровая сессия ввода, три области VContainer и одна
загруженная сцена. В поиске насчитан 321 сценовый объект и один EventSystem.
В двух поселениях по 64 объекта. Предыдущие область, игрок и обработчик
сцены уничтожались. С записью Profiler выделенная память поиска выросла
с 1029,8 до 1327,0 МиБ до правки и с 969,5 до 1277,7 МиБ после. В отдельном
прогоне без записи Profiler память выросла с 894,5 до 900,3 МиБ.
Это измерение включает Editor и не устанавливает долгосрочный предел.

## Приёмка

- Дом и старьёвщик прошли по 9 проверок холодного входа из существующих
  слотов. Отдельная проверка координатора заблокировала `slot.pending`,
  убедилась в сохранении старого слота и выгрузке подготовленной сцены,
  затем успешно повторила отправление с вылазки 2 на 3. Полный дополнительный
  Editor-сценарий отказов остановился на виртуальном Enter и в итог проверок
  не включён.
- Development Player с временным Pipeline Runtime прошёл `offer`, `resume`
  и `finished` в трёх процессах (30 + 23 + 5 проверок в RU). Проверены
  первая продажа, две попытки с пропуском, гарантированная модель, F5,
  продолжение из сохранённой укладки, осмотр, подбор, предъявление, сохранение
  вещи и однократное открытие контакта. Сборка Development имеет результат
  Succeeded. В BuildReport есть шесть ошибок интерфейса Project Browser,
  а в Player.log четыре сообщения о шейдерах эффектов постобработки.
- Итоговый Release расположен в `Builds/I-190/TrashHunterWorld.exe` и
  использует четыре игровые сцены. Рядом лежит `THIRD_PARTY_NOTICES.md`.
  Pipeline Runtime выключен. Сборка `build_20926feacc6c` завершилась с нулём
  ошибок и предупреждений. Проверены запуск и выход с кодом 0 на копии
  слота старьёвщика. Полный квест проверен на Development Player.
- Во время первого захвата после изменения Unity завершился аварийно.
  Причина по логу не установлена. После восстановления повторные захваты
  и три запуска квеста завершились. Первый ошибочный прогон до настройки
  изоляции изменил основной Editor-слот. Полученные тогда замеры исключены,
  версии 137 и 136 сохранены для сверки в
  `Logs/I-190/editor-slot-after-incident/`. Прежний слот не восстановлен.
  Измеритель теперь требует существующую тестовую копию в `Logs/I-190/`.

Подробные логи и профили находятся в `Logs/I-190/`. Плейтест владельца
добровольный. Для ручной сверки в Player продать вещь старьёвщику,
принять поручение через J, найти РП-07, перезапустить игру и предъявить
его через P. После подтверждения проигрыватель остаётся в запасе, J
показывает результат с контактом мастера.
