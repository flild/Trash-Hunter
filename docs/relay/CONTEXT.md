# Контекст разработки прототипа

Корень — `F:\UnityProjects\Trash-Hunter`, Windows / PowerShell. Источники — [инструкции проекта](../../AGENTS.md), [состояние](../PROJECT_STATE.md), [решения](../DECISIONS.md) и [план прототипа](../design/PROTOTYPE.md). Проектирование завершилось в D-080. [Итог прежней эстафеты](../sessions/2026-11-24-relay-closure.md) сохранён.

**Распределение работы.** По запросу владельца от 24.11.2026 агент выполняет реализацию, создаёт ассеты через Editor, запускает проверки, собирает и исправляет прототип, ведёт документацию и передаёт следующий этап. Обычные технические решения принимает самостоятельно в рамках согласованной архитектуры. При существенном выборе, меняющем поведение или архитектуру, агент сообщает варианты с последствиями и сохраняет решение владельца. Ручной шаг запрашивает только после диагностики конкретного препятствия, например если Unity требует личного входа. Указывает одно точное действие и ожидаемый результат, затем продолжает сам.

**Техническая отправная точка.** I-010 проверен в Unity 6000.6.9f1 с Unity Pipeline 1.0.0, Input System 1.20.1 и uGUI 2.6.0. VContainer 1.19.0 зафиксирован по ревизии в manifest и lock. [DEVELOPMENT](../DEVELOPMENT.md) описывает команды Editor и Player. Сцены, префабы и их связи создаются через Editor.

**Результат I-040.** В ContainerSearch три чередующиеся укладки из 24
подвижных экземпляров и 12 определений. Две лампы занимают по 2 × 2.
Цена и состояние выбранного экземпляра показаны на домашнем экране сделки.
[GameState](../../Assets/TrashHunter/Runtime/GameState.cs) открывает также
пять исходных экземпляров в уже начатой вылазке I-030. Новое отправление
использует актуальную укладку. Сборка и прогон — в
[отчёте I-040](../sessions/2026-11-25-i040-windows-playtest.md).
Пороги C-111 и частота контрольных снимков ожидают согласования по
[замерам I-030](../sessions/2026-11-25-i030-expedition-save.md#замеры-для-c-111).

**Что решено.** Одна сцена поиска в I-010, отдельные префабы игрока с камерой и HUD, uGUI, VContainer и области приложения, прохождения и сцены закреплены в C-098–C-100 и C-114. Ручная сетка, потеря предмета в руке при подтверждённом уходе и возобновление вылазки после обычного выхода заданы в [CORE_LOOP](../design/CORE_LOOP.md). Идея с шарниром лампы — пример для проверки C-115. Статистику участников, удовольствие от игры и желание повторить вылазку можно записывать только по наблюдениям за людьми.

**Приёмка без ручного тестирования владельцем.** Агент сам готовит локальную сборку и повторяет маршрут игрока. Участники плейтеста привлекаются при доступности. Если их нет, агент передаёт работающий прототип, фиксирует «0 участников», технический результат и открытый вопрос об интересе. Решение принять результат с этим ограничением либо вернуться к наблюдению принадлежит владельцу. Сами по себе действия агента не выполняют критерий «3 из 5» и не дают оснований расширять объём.
