## Как вести комплект дизайна

Порядок обсуждения после ревизии: главное удовольствие и путь развития →
действия и вылазка → предметы и переноска → экономика и прогрессия →
еда и последствия → причинный сюжет → визуал/звук/UX → архитектура →
объём продукта, качество и поддержка → итоговая проверка комплекта.
Точные ID, зависимости и критерии находятся только в BACKLOG.

Для каждого раздела нужны: правило, пример игровой ситуации, исключения,
проверяемый результат и явный статус решения. Уточняем по одной теме за сессию.
Точный баланс и физическую устойчивость письменно доказать нельзя: после
согласования дизайна проверим их в первом рабочем срезе, затем обновим документы по результату.

Итог проектирования — согласованный комплект по этой карте: правила, примеры,
история от начала до конца, путь прогрессии, границы систем, процесс разработки,
сценарии проверки и реестр решений. Дублировать всё в ещё одном большом GDD не нужно.
Актуальный результат — в [итоговой сверке D-080](design/DESIGN_REVIEW.md#итоговая-сверка-d-080).

Готовность документации проверяется в BACKLOG D-080. Для начала кода дополнительно
нужны ограниченная первая задача и прямое разрешение владельца на реализацию.
Полностью писать все реплики и выбирать каждую декоративную модель до первого
рабочего среза не требуется; сюжетный каркас, правила и ограничения должны быть согласованы.
